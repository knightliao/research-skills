# 字幕处理规则

## 输入与识别

支持 SRT、WebVTT、ASS/SSA、LRC、TXT 和 Markdown。优先使用文件内容特征识别格式，再以扩展名兜底；两者冲突时采用内容特征并复核正文。无法可靠识别时使用 `--format`，不得凭感觉选择。

编码按以下顺序处理：

1. 读取 BOM，明确识别 UTF-8、UTF-16 或 UTF-32；
2. 无 BOM 时严格尝试 UTF-8；
3. UTF-8 失败后，只检查脚本支持的有限传统编码候选；
4. 只有一个候选能够严格解码且文字系统合理时才采用；
5. 多个候选合理时停止，要求用户使用 `--encoding`；
6. 不得使用替换字符掩盖解码错误。

## 格式清理

- **SRT**：移除 cue 序号和时间轴，合并同一 cue 的显示换行。
- **WebVTT**：移除文件头、cue 标识、时间设置以及 `NOTE`、`STYLE`、`REGION` 块；把可识别 voice 保留为讲者。
- **ASS/SSA**：只读取 `[Events]` 中的 `Dialogue`，依据 `Format` 定位 `Text` 和 `Name`/`Actor`，保留正文逗号，处理 `\N`、`\n`、`\h` 与覆盖样式。
- **LRC**：删除元数据、行首时间标签和增强型行内时间标签，保留歌词或讲话内容。
- **TXT/Markdown**：只删除能够明确构成字幕 cue 的序号和时间轴；保留标题、列表、段落和讲者标签。

统一换行，执行 Unicode NFC 规范化，压缩无意义水平空白，移除受支持的样式标签。不要修复专有名词、数字或事实；这些不属于确定性清洗。

## 精确去重

只执行以下两类去重：

1. 同一讲者的相邻 cue 或相邻文本行在规范化后完全相同，删除后一个；
2. 相邻带时间 cue 存在严格相等的最长“前一条后缀—后一条前缀”，且交叠位于完整文本或明确的空白、标点边界，合并并只删除相同交叠部分。

不使用编辑距离、字符相似度、关键词重合、同义判断或语义去重。讲者不同、文字只近似、边界不明确或无法证明为滚动重复时全部保留。TXT 和 Markdown 只删除直接相邻的完全相同行，不推断滚动重叠。

## 语言判断

- 有效语义基本为中文：按中文字幕处理。
- 有效语义基本为一种或多种外语：按外语字幕处理。
- 中文与外语都承担实质信息：按混合字幕处理。
- 产品名、代码、缩写或惯用英文术语不单独构成混合字幕。

语言判断是语义任务，不写入规范化脚本。

## 全局内容底稿

先完整理解字幕，再写文章。底稿至少记录：

- 主题与讲述目的；
- 核心观点及其重要程度；
- 观点之间的因果、递进、转折和条件关系；
- 支撑论据、案例、反例和类比；
- 数字、单位、时间与比较基准；
- 适用范围、前提、例外和不确定性；
- 每项观点的讲者归因；
- 无法可靠解释但可能影响结论的歧义。

长字幕可以按自然话题边界分块。每一块只更新同一份底稿；处理完全部块后统一解决重复、冲突和排序，再开始写作。不得为每块先写小文章再拼接。

## 异常处理

- 文件不可读、内容为空、清洗后无正文：停止并说明原因。
- 编码歧义：要求用户指定 `--encoding`。
- 格式歧义：要求用户指定 `--format`。
- 字幕明显截断：仍可处理时说明文章只覆盖现有内容，不补写缺失部分。
- 关键名字、数字或句子含混：保留原文或明确不确定，不能猜测。
