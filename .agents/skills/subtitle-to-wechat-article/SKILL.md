# 字幕转中文公众号文章

## 目标与默认值

把字幕转换为一篇可以直接编辑发布的中文公众号文章，而不是字幕摘要或逐句译稿。

- 默认读者：愿意理解主题的普通中文读者。
- 默认文体：编辑转述体；可识别讲者时保留归因，不可识别时不虚构身份。
- 默认篇幅：随有效信息量自适应。
- 默认格式：公众号文章包；主标题单独交付，正文包含导语、二级分节和结语。
- 默认边界：只使用字幕提供的信息，不联网补写背景、数据、事实或案例。

当用户已经选择本 Skill，并且询问如何使用、要求可复制输入、当前输入明显缺少必要材料，或需要帮助选择源稿修改、新版本、incomplete 恢复、状态查询及图片模式时，按需读取：

## 自然语言意图路由

用户不需要记忆 CLI 参数或完整磁盘路径。先解析意图并定位相关源稿与文章包；意图明确且候选唯一时，用一句话说明本次会“只修改源稿”“创建新版本”“继续指定 incomplete 包”或“只读查询”，然后直接执行。只有候选不唯一或意图相互冲突时才询问。

| 用户意图 | 固定行为 |
| --- | --- |
| “修改、润色、压缩、扩写、调整文章”，例如“把开头压缩一下” | 只定位并修改包外的可编辑源稿，到此停止。不得运行 `init`、`rebuild`、图片生成或 `finalize`，也不要求源稿达到 complete。 |
| “重新生成、重新打包、生成公众号版本、准备发布”，例如“用修改后的文章重新生成” | 从当前外部源稿创建新的、不可覆盖的 `-vN` 发布包；随后按该新包的模式补齐资产并完成发布流程。 |
| “切换模式”，例如“改成只要封面” | 基于当前外部源稿创建新的 `cover-only` 或 `body-images` 版本，不修改任何旧包。 |
| “继续、补齐、完成”，例如“继续上次失败的包” | 操作用户指定或唯一匹配的 incomplete 包，保留全部 ready 资产，只补缺失项；不得重新创建包或覆盖已有资产。 |
| “恢复历史版本”，例如“从 v2 恢复成草稿” | 将历史包中的 `article.md` 快照复制为包外的新可编辑源稿，不修改历史包，也不自动打包。新源稿不得覆盖已有文件。 |
| “查看状态、列出版本” | 只读展示源稿和文章包信息，不修改任何文件。 |

候选定位严格按以下优先级：显式路径或版本、当前对话上下文、schema v2 manifest 关联、唯一候选。通过 manifest 的 `article_source_file`、`source_file`、`package_version`、`mode` 和 `status` 关联源稿、来源字幕与发布包。

存在多个合理候选时，必须展示每个候选的源稿路径、包版本、模式和状态，再询问用户选择“修改草稿、继续旧包或创建新包”；禁止仅按修改时间、目录排序或其他隐式启发式静默选择。无法同时满足的意图也必须先说明冲突并询问。

## 主工作流

1. **确认输入**：接收一个 SRT、WebVTT、ASS/SSA、LRC、TXT 或 Markdown 文件。文件不可访问、为空或格式不受支持时，停止并说明问题。
2. **规范化字幕**：在 Skill 目录执行 `python3 scripts/normalize_subtitle.py <input> -o <temporary-output>`。需要覆盖自动识别时使用 `--encoding` 或 `--format`。编码存在歧义时不得猜测，要求用户明确指定 `--encoding`。
3. **检查清洗结果**：确认正文非空、顺序合理、讲者信息仍可辨认。脚本只清理确定性结构，不把其 stderr 诊断写进文章。
4. **判断语言**：按有效语义判断中文字幕、外语字幕或混合字幕。零散产品名、代码或惯用术语不单独构成混合语言。
5. **建立中文语义底稿**：中文字幕直接提取语义；外语字幕先准确翻译；混合字幕只翻译外语部分。记录主题、观点、论证、案例、数字、限定条件、讲者归因和歧义项。
6. **处理长字幕**：可以按语义段分块读取，但每块只更新同一份全局底稿。全部读取后统一消歧、去重和排序，禁止把各块摘要串接为正文。
7. **重组文章**：确定单一主线，按读者理解顺序而非字幕时间轴组织内容。删除口头禅和无信息重复，保留支撑结论所需的观点、论证、案例、数字、反例与限制。
8. **生成或修改可编辑源稿**：在文章包之外保存最终 Markdown，包含一个主标题、导语、二级分节正文和结语；源稿不得包含图片引用。若路由结果只是修改源稿，在此结束，不进入打包流程。
9. **按发布意图初始化快照**：只有路由结果是重新生成、打包、发布或切换模式时才创建新包。默认运行 `init ... --mode cover-only`；用户显式要求正文配图时，在源稿之外编写 `illustration-plan.json`，并以 `--mode body-images --illustration-plan <plan>` 初始化。每次都创建新版本，包内文章与计划不得修改。
10. **按需重建新版本**：用户明确要求基于旧包重新生成时，运行 `rebuild <old-package> --article <current-article> --mode ...`。`rebuild` 只读旧包并创建 `-vN`；普通文章修改不得自动触发 rebuild。
11. **生成真实图片**：默认只编写 `cover` 提示词并运行 `set-prompts`，生成一张无文字横版封面，再通过 `add-image --role cover` 安装为 `cover.png`。body-images 模式再按冻结计划生成和安装正文图。不得使用占位图。
12. **完成文章包**：运行 `finalize`，生成 `wechat-body.html`、`publish-guide.md` 和 complete manifest。incomplete 包只能补齐当前快照缺少的资产；图片生成失败时运行 `fail` 并明确说明未完成。
13. **最终检查**：逐项执行质量检查清单。发现编造、模态改变、错误归因、关键限定条件遗漏、局部摘要拼接或文章包校验错误时，必须修订后再交付。

## 语言与忠实度规则

- 中文字幕直接文章化，不先改写成另一份逐句稿。
- 外语先形成准确、自然的中文语义底稿，再据此写作，不把逐句译文直接当正文。
- 混合语言只翻译实质性外语内容；公司名、产品名、项目名、代码和必要术语保留官方形式。
- 保持数字、单位、日期、比较关系、否定、时态、因果和范围不变。
- 不把“可能”“计划”“尝试”“尚未验证”改成“已经”“必然”或确定事实。
- 不把讲者的判断、预测或经验包装成客观事实；多讲者内容不得混淆立场。
- 字幕含混时不得猜测。关键歧义保留原文或明确不确定性；非关键噪声可以省略。

## 输出契约

### 只修改源稿

- 修改包外的可编辑 Markdown，保持一个主标题、导语、二级分节正文和结语，并执行忠实度检查。
- 不运行打包、图片或 finalize 流程，不要求交付 complete 包。
- 完成后明确说明修改的源稿路径，并明确写出“未创建发布包”。
- 恢复历史版本也适用此契约：报告新源稿路径和来源版本，不修改旧包。

### 创建发布包

- 从当前源稿创建新的不可覆盖 `-vN` 包；主标题写入 `title.txt`，HTML 正文不重复主标题，二级标题稳定放大、加粗。
- 图片工具临时文件不算交付；默认校验真实 `cover.png`，body-images 模式再校验计划列出的正文图。
- 只有此类任务要求最终状态为 complete。若受外部图片生成等问题阻塞，必须保持 incomplete 并准确报告，不能宣称发布包已经完成。

### 继续 incomplete 包

- 只操作已明确选定的 incomplete 包，保留 ready 提示词和图片，只补齐 manifest 当前列出的缺失或无效项。
- 成功时完成 finalize；仍有阻塞时保留 incomplete 和已有成果，不重建包、不切换模式、不改文章快照。

### 只读查询

- “查看状态、列出版本”只读取外部源稿和 manifest，不写入源稿、文章包或报告。
- 展示足以区分候选的源稿路径、包版本、模式、状态和当前阻塞项。

所有文章内容都必须连贯、易读，不输出处理日志、逐句译文、摘要列表或质量报告。只保留一个主标题，不用夸张标题；段落围绕清晰意思展开，删除模板占位符和内部底稿。complete 包永久只读。用户明确要求其他篇幅、受众或口吻时优先遵循，但仍执行忠实度与事实边界规则。
