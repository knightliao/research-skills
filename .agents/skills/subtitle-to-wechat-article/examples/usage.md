# Subtitle to WeChat Article 用户使用示例

## 这个 Skill 适合什么

`subtitle-to-wechat-article` 将 SRT、WebVTT、ASS/SSA、LRC、TXT 或 Markdown 字幕清理、翻译并重组为中文公众号文章。它也会校准疑似机翻或译制中文字幕中的术语与语序，同时保留观点、论证、案例、数字、讲者归因和限定条件，不联网补写字幕中不存在的事实。若文章是用户访谈，联网仅用于确认并获取主人公头像作为配图素材，检索结果不会写入正文。

默认交付 `cover-only` 公众号文章包：包外可编辑 Markdown 源稿，以及包内不可变发布快照、独立标题、稳定样式 HTML、真实无字封面、发布指南和 manifest。封面会先从全文提炼内容—视觉映射，不使用可任意套换文章的通用模板；只有用户显式要求时才进入 `body-images` 正文配图模式。

## 调用方式

通过当前宿主提供的 Skill 入口选择 `subtitle-to-wechat-article`，再提供字幕或已有源稿、文章包路径。不同宿主的具体选择方式可能变化；完整宿主说明见仓库根 README。

## 使用前准备

- 新建文章：一个可访问的字幕文件路径，格式为 SRT、WebVTT、ASS/SSA、LRC、TXT 或 Markdown。
- 可选信息：目标读者、文章口吻、篇幅倾向、需要保留的术语或官方名称，以及是否显式需要正文配图。
- 用户访谈：尽量提供核心受访者姓名、官方主页或有权使用的头像；多人访谈时明确指定封面主人公。
- 修改或重建：包外可编辑 Markdown 源稿路径，以及相关发布包路径或版本。
- 继续未完成任务：明确的 incomplete 包路径；若存在多个候选，准备选择具体版本。
- 查看状态：源稿目录、文章包目录、明确路径或版本。

## 快速开始

下面是最短的可复制输入：

```text
请将下面的中文字幕生成微信公众号文章包。

字幕文件：
<字幕文件路径>

使用默认模式。
目标读者：
<目标读者>

文章风格：
<风格要求>
```

**预期交付**

默认生成包外可编辑 Markdown，并创建新的 `cover-only` 发布包。完成包包含 `title.txt`、`article.md` 快照、`image-prompts.md`、真实 `cover.png`、`wechat-body.html`、`publish-guide.md` 和 complete `manifest.json`。封面提示词会映射文章的核心主题、中心张力和语气；若内容被判定为用户访谈，会先确认唯一主人公、获取可信头像，再按该映射微修为封面主视觉。人物、头像或内容映射无法可靠确认时会请求用户补充素材。若图片生成受阻，会保留可继续处理的 incomplete 包并准确报告阻塞，不能把它宣称为完成包。

## 常见场景

### 场景一：将中文字幕生成默认文章包

**适用场景**

已有完整或可用的中文字幕，希望得到可编辑文章和可发布公众号包。

**使用前准备**

- 中文字幕文件；
- 可选的目标读者、风格和篇幅要求；
- 文章包输出位置由当前工作环境确定。

**可复制输入**

```text
请将下面的中文字幕生成微信公众号文章包。

字幕文件：
<字幕文件路径>

使用默认模式 cover-only。
目标读者：
<目标读者>

文章风格：
<风格要求>
```

**预期交付**

清洗字幕后直接建立中文语义底稿，按单一主线重组文章；交付包外源稿和一个带真实无字横版封面的新发布包。封面至少通过两项可见选择映射文章内容，不能只做横版裁切或通用科技背景。若文章是用户访谈，封面会先确认核心受访者，再基于其可信头像和文章视觉简报进行克制微修；不会直接生成一个相似人物冒充本人。正文不含图片引用。

**注意事项**

默认模式只要求封面，不自动生成正文配图。字幕表面为中文但疑似机翻、译制或术语密集时，仍会先建立内部术语簿并按语境校准；字幕明显截断时，文章只覆盖现有内容，不补写缺失部分。

### 场景二：翻译外语、混合或疑似机翻字幕并文章化

**适用场景**

字幕主要为英文、其他外语、中外语混合，或表面为中文但存在明显机翻腔、译制痕迹和术语漂移，需要先形成准确中文语义底稿再写成文章。

**使用前准备**

- 外语、混合语言或疑似机翻与译制的中文字幕文件；
- 目标读者和文体；
- 需要保留原文的术语或官方名称。

**可复制输入**

```text
请将下面的外语、中外语混合或疑似机翻中文字幕校准为自然中文，并生成微信公众号文章包。

字幕文件：
<字幕文件路径>

要求：
- 保留原意；
- 去除字幕口语和重复；
- 重组为适合公众号阅读的文章；
- 不虚构原字幕中不存在的观点；
- 保留产品名和技术术语的官方形式；
- 同一术语按语境统一，不机械替换同形异义词。
```

**预期交付**

先生成准确、自然的中文语义底稿；疑似机翻、译制或术语密集时另建内部术语簿，再从全局主线写作。数字、日期、否定、时态、条件、讲者归因和不确定性保持不变，最终交付与默认模式一致的文章包。

**注意事项**

不会把逐句译稿直接拼成正文，也不会因为字幕表面为中文就跳过术语校准。关键歧义会保留原文或明确说明不确定性，不会联网猜测名字、数字、术语原文或背景。

### 场景三：显式生成带正文配图的新包

**适用场景**

除了封面，还需要 1～4 张与文章章节和段落位置绑定的正文图片。

**使用前准备**

- 字幕文件或包外可编辑源稿；
- 明确要求 `body-images` 模式；
- 希望图片帮助解释的章节或概念。

**可复制输入**

```text
请将下面的字幕生成微信公众号文章包，并显式使用 body-images 模式。

字幕文件：
<字幕文件路径>

正文配图要求：
- 只使用 1～4 张真正有助于理解的图片；
- 图片不得补充字幕之外的事实、数字或案例；
- 每张图必须绑定明确章节和段落插入位置；
- 同时生成真实无字横版封面。
```

**预期交付**

除默认交付外，新包还包含冻结的 `illustration-plan.json` 和通过校验的 `images/body-NN.png`；HTML 按计划插入正文图，发布指南列出每张图的位置。

**注意事项**

正文图片必须由用户显式要求。模式、文章或插图计划发生变化时必须创建新版本，不能修补旧包。

### 场景四：只试一张配图或封面预览

**适用场景**

想先验证人物选择和视觉方向，不希望现在创建公众号发布包。

**使用前准备**

- 字幕文件、现有文章或可访问的 Markdown 源稿；
- 希望预览封面还是正文图；
- 用户访谈尽量提供核心受访者姓名或官方头像来源。

**可复制输入**

```text
请根据下面的字幕先试一张无文字横版封面预览：

字幕文件：
<字幕文件路径>

请先从全文提炼内容—视觉映射；如果是用户访谈，先确认主人公并使用可信头像做轻度适配。
这次只预览图片，不创建发布包，也不要在仓库中创建 output 或其他通用图片目录。
```

**预期交付**

展示一张经过内容适配的图片，说明人物头像来源以及至少两项“文章线索 → 视觉表达”映射，并报告宿主图片工具返回的实际文件路径。结果会明确标记“未创建发布包；当前图片不是正式发布资产”。

**注意事项**

预览图保留在宿主图片工具默认目录或仓库之外的临时路径，不写入仓库 `output/`。之后若确认发布，需要另行创建新版本，并通过 `add-image` 安装到包内固定路径，不能手工复制预览图。

### 场景五：只修改包外 Markdown 源稿

**适用场景**

已有与发布包关联的可编辑源稿，只想润色、压缩、扩写或调整结构，暂时不重新发布。

**使用前准备**

- 包外 Markdown 源稿路径，或能够唯一定位源稿的文章包；
- 具体修改要求；
- 需要保持的事实、段落或语气。

**可复制输入**

```text
请只修改下面的包外可编辑 Markdown 源稿：

源稿：
<Markdown 源稿路径>

修改要求：
- <例如：把导语压缩为两段>
- <例如：保留所有数字和限定条件>

不要创建或重建发布包，不要生成图片，不要运行 finalize。
```

**预期交付**

只更新指定的包外源稿，并报告实际路径和“未创建发布包”。旧发布包及其快照保持不变。

**注意事项**

该模式不要求源稿达到 complete 包状态。若存在多个合理候选，Agent 会先列出源稿路径、包版本、模式和状态，再要求选择。

### 场景六：从修改后的源稿创建新版本

**适用场景**

已经完成源稿修改，现在需要重新打包或准备发布，同时保留全部历史版本。

**使用前准备**

- 当前包外源稿路径；
- 关联的旧包路径或来源字幕；
- 新版本需要的 `cover-only` 或 `body-images` 模式。

**可复制输入**

```text
请使用修改后的包外源稿创建新的公众号发布版本。

当前源稿：
<Markdown 源稿路径>

关联旧包：
<旧文章包路径>

新版本模式：
<cover-only / body-images>

不要修改或覆盖旧包。完成新包所需的图片和校验流程。
```

**预期交付**

创建新的不可覆盖 `-vN` 包，冻结当前文章快照和可选插图计划，补齐真实图片并在条件满足时 finalize；旧包保持逐字节不变。

**注意事项**

普通文章修改不会自动触发重建。只有“重新生成、重新打包、准备发布或切换模式”等明确意图才创建新版本。

### 场景七：继续一个 incomplete 包

**适用场景**

上次文章包因提示词、图片或其他可补齐资源而未完成，希望保留已有成果继续处理。

**使用前准备**

- 明确的 incomplete 包路径或唯一候选；
- 当前阻塞信息；
- 补齐缺失资源所需的图片生成能力。

**可复制输入**

```text
请继续完成下面的 incomplete 公众号文章包：

文章包：
<incomplete 包路径>

保留全部已经 ready 的提示词和图片，只补 manifest 当前列出的缺失或无效项。
不要重建文章包，不要切换模式，不要修改 article.md 快照。
```

**预期交付**

只操作选定的 incomplete 包，保留所有 ready 资产；成功时生成 HTML 和发布指南并把状态变为 complete，仍受阻时保留 incomplete 状态和已有成果。

**注意事项**

不会覆盖正式目标文件，也不会通过重新创建包来绕过错误。complete 包永久只读，不能用此场景继续修改。

### 场景八：只读查看版本和状态

**适用场景**

需要了解有哪些源稿和发布版本、各自模式、状态及当前阻塞，但不希望修改文件。

**使用前准备**

- 源稿或文章包所在目录；
- 可选的具体字幕名称、源稿路径或版本。

**可复制输入**

```text
请只读查看下面目录中的公众号文章源稿和发布包状态：

目录或文章包：
<路径>

列出：
- 源稿路径；
- 包版本；
- 发布模式；
- complete 或 incomplete 状态；
- 当前阻塞项。

不要修改任何文件。
```

**预期交付**

一份只读状态清单，提供足以区分候选的源稿路径、包版本、模式、状态和阻塞项；不会写入源稿、文章包或额外报告文件。

**注意事项**

如果多个候选都合理，不会按修改时间静默猜测当前版本，而会展示候选并请用户选择后续动作。

### 场景九：从历史版本恢复为新草稿

**适用场景**

需要继续编辑某个历史发布快照，但不能修改已封存的历史包。

**使用前准备**

- 明确的历史包路径或版本；
- 新草稿希望保存的位置。

**可复制输入**

```text
请从下面的历史文章包恢复一份新的包外可编辑草稿：

历史包：
<历史文章包路径>

不要修改历史包，不要自动重新打包，也不要覆盖已有源稿。
```

**预期交付**

将历史包中的 `article.md` 快照复制为新的包外可编辑源稿，报告新源稿路径和来源版本；不自动创建发布包。

**注意事项**

如果目标文件已存在，必须换用新的安全路径，不能覆盖。

## 不适用场景

- 没有字幕或正文素材，却要求凭空生成事实性文章：应先提供可靠原始材料。
- 要求直接修改已 complete 的封存发布包：应恢复或修改包外源稿，再创建新版本。
- 要求生成视频、动画或需要长期有效外部媒体托管：当前 Skill 只交付文章、HTML 和真实本地 PNG。
- 只想润色一篇与字幕流程和文章包无关的普通 Markdown：使用普通编辑 Agent 更直接。
