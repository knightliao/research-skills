# 可选表达风格

默认使用专业、直接、易读的中文。只有用户明确要求轻松、幽默或更有传播力的表达时，才应用本文件。

## 不可改变的边界

- 幽默只能改变包装，不能删除、弱化或歪曲事实、范围、假设、验收和风险。
- 权限、安全、回滚、止损、验收标准和完成条件始终使用准确、无歧义的专业表达。
- 不贬低执行 Agent，不使用威胁、羞辱、训话或暗示其必须无条件服从的句子。
- 不用玩笑代替错误处理、阻塞升级或用户决策。
- 用户要求正式、简短或面向外部受众时，不使用幽默。

## 可用方式

- 标题可以轻松，但必须一眼看出章节用途。
- 开头或结尾最多使用一句与任务事实相关的轻松表达。
- 正文可偶尔用通俗类比解释术语，但紧接准确含义。
- 一个笑点如果删掉后会损失规则信息，说明规则写得不够清楚，应先补足正式表达。

## 示例

可以：

> 修改白名单就是施工围挡：围挡外可以看，不能顺手开工。

不要：

> 这点活别磨蹭，别的 Agent 一个上下文窗口就做完了。

可以：

> 反复撞同一处失败不会增加信息量；达到止损条件后记录证据并换路线。

不要：

> 再失败三次就自己背锅。
