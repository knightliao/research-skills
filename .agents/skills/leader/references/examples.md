# 任务指导示例

示例展示结构和颗粒度，不是可直接套用的固定句式。真实任务必须先检查对应仓库和约束。

## 示例一：修改一个 Python Skill

用户请求：

> CREATE：修改一个 Python Skill，让它拒绝缺少日期的事件记录。

输出节选：

```text
# 为事件记录增加日期校验

## 1. 背景与目标
当前事件校验允许缺少日期的记录进入后续流程。完成后，缺少日期或日期格式错误的记录应被确定性拒绝，并返回可定位字段的错误。

## 2. 已知事实
- 已验证事实：入口为 `scripts/validate_events.py`，现有测试位于 `tests/test_validate_events.py`。
- 已验证事实：仓库要求 Python 3.11 以上且只使用标准库。
- 根据仓库推断：日期应沿用现有 `YYYY-MM-DD` 表达；开始前核对 schema 和已有样例。

## 3. 默认决策与假设
- 决策：不自动补全缺失日期。理由：补全会把推断写成事实。猜错影响：可能拒绝旧数据。发现存在兼容要求时，停止该部分并记录需要的迁移决策。

## 4. 修改范围
- 可修改：日期字段契约、对应校验脚本和测试。
- 其余 Skill、框架和打包工具只读。

## 5. 非目标与禁止事项
- 不修改其他字段语义，不增加第三方依赖。
- 不删除测试、放宽断言或吞掉失败。

## 6. 实施步骤
1. 核对 schema、有效样例和无效样例。
2. 先增加缺失日期与错误格式的失败测试。
3. 在现有校验入口实现最小修改。
4. 更新字段契约并运行目标测试与仓库校验。

## 7. 验收标准
- 行为：有效日期通过；缺失或格式错误时返回非零状态和字段级错误。
- 自动化：运行仓库实际存在的目标测试和 Skill 校验，贴出结果摘要。
- 守约束：范围外无修改，测试数量和强度不下降，无新增依赖。
```

## 示例二：设计 MCP Server，暂不编码

用户请求：

> CREATE：调研并设计一个读取内部知识库的 MCP Server，先不要编码。

输出节选：

```text
# 内部知识库 MCP Server 调研与设计

## 1. 背景与核心问题
需要判断现有知识库是否适合通过 MCP 暴露只读检索，并形成可供后续评审的接口和安全设计。本阶段不实现服务器。

## 2. 判断标准
- 能否使用最小权限完成检索；
- 是否支持身份映射、结果级授权和审计；
- 搜索质量、延迟和运维成本；
- 敏感内容是否可能跨用户泄露。

## 3. 已知事实与未验证事项
- 用户决策：本阶段只调研和设计，不编码。
- 待执行 Agent 验证：知识库 API、身份模型、速率限制和审计能力。
- 根据现有描述推断：首版只需只读搜索和单篇读取；不得把该推断写成已批准范围。

## 4. 信息来源
优先官方 API、认证和权限文档；对权限行为至少用两个不同角色的最小实验交叉验证。

## 5. 研究步骤
1. 盘点数据源、认证和授权边界。
2. 比较直连 API、代理服务和预建连接器。
3. 设计候选 tools、输入输出、错误和审计字段。
4. 完成威胁模型和最小权限方案。

## 6. 输出要求
交付方案比较、推荐架构、tool 草案、权限模型、风险清单、验证计划和未决问题。事实附来源或复现步骤，推断与建议单列。

## 7. 阶段门
提交设计评审后停止。只有用户另行授权实施，才创建或修改代码、配置与部署资源。
```

## REVIEW-SPEC 示例

默认输出局部修订，而不是重写全文：

```text
## 复核结论
需要修改。

## 问题分级
### 阻塞
- “运行全部测试”没有给出实际命令，执行者无法判定使用哪个测试入口。

### 重要
- 修改范围只列目录，没有冻结现有验收脚本。

## 建议替换段落
将“运行全部测试”替换为：“先从项目配置确认测试入口；已验证命令为 `<命令>` 时运行它，否则记录待验证并不得编造。”
```

## AUDIT-RESULT 示例

```text
## 验收结论
部分通过。

## 已验证结果
- 目标测试通过：实际运行 `<命令>`，结果为 18 项通过。

## 工作树变化归因
- 验收前已有 2 个未提交文件；本次验证未修改它们。
- 验证新增 `.pytest_cache/`，属于临时文件，未擅自删除。

## 未运行或证据不足
- 未运行集成测试：本地缺少任务书要求的服务凭据。

## 遗留风险与下一步
- 需在具备测试凭据的环境补跑集成测试后才能判定完全通过。
```
