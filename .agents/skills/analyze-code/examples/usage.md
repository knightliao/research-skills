# 代码分析用户使用示例

## 这个 Skill 适合什么

`analyze-code` 用于帮助你快速看懂一段陌生代码：先说明它整体做什么，再还原真正的执行路径，最后按代码形态使用逻辑阶段、职责与方法、文件模块或入口处理链解释实现。它适合 Python、JavaScript、TypeScript、Java、Go 等常见代码，也能在证据不足时把语言或框架保持为未知。

它默认只做静态理解，不运行、修改或 Review 代码，也不主动寻找 Bug、安全问题或性能优化点。

该 Skill 只支持显式调用。每次使用前都需要输入 `$analyze-code`，或通过当前宿主的 Skill 入口选择“代码分析”；只粘贴代码或只说“帮我看懂”不会自动启用。

## 使用前准备

- 准备要理解的代码，直接粘贴即可，不需要转换成 JSON。
- 可以补充代码来源或业务背景，但不需要填写语言、框架、文件名和入口。
- 如果代码很长，可以说明最关心的模块；即使不说明，Skill 也会先给出完整模块地图和主链路。
- 无论是否附带理解说明，都请先通过 `$analyze-code` 或当前宿主的 Skill 入口显式选择本 Skill。

## 快速开始

下面是最短的可复制输入：

```text
$analyze-code

帮我看懂下面这段代码：

<直接粘贴代码>
```

**预期交付**

结果固定依次包含“一句话说明”“核心流程”“代码详细分析”。核心流程会把正常路径与关键分支分开，并按理解难点选择调用链、数据流、状态迁移、分支结果或生命周期中的主要视角；详细分析使用匹配代码形态的结构地图和稳定行号，不重复上文已经讲清的结论。

## 常见场景

### 场景一：自然语言说明加代码

**可复制输入**

```text
$analyze-code

这是 MCP Server 的鉴权逻辑，请帮我解释它主要怎么运行：

<代码>
```

**预期交付**

先说明鉴权逻辑的整体目的和真实触发方式，再选择最有帮助的调用或分支视角解释主路径。代码没有展示的外部认证服务实现会集中标为未知。

### 场景二：显式选择后直接粘贴

**可复制输入**

```text
$analyze-code

<代码>
```

**预期交付**

显式选择本 Skill 后无需额外说明。Skill 会自行识别代码正文；语言、框架或入口证据不足时会如实说明，而不是强行分类。

### 场景三：分析较长代码

**可复制输入**

```text
$analyze-code

请先让我理解完整结构和主执行路径，再按模块解释下面的长代码：

<几百行或更长的代码>
```

**预期交付**

整体目的和主路径保持完整，结构地图覆盖全部输入；局部解释深度按入口、关键分支、状态变化和外部副作用的重要性分配。一次无法展开全部细节时，会列出已展开、部分展开和未展开的结构及行号范围。

### 场景四：只想修复或审查代码

下面的请求不会触发本 Skill，因为没有显式选择 `$analyze-code`，而且目标是修改和测试：

```text
请修复这段代码的异常，并补充测试：

<代码>
```

此时应直接使用相应开发流程。`analyze-code` 不会因代码块、理解意图或其他自然语言请求而自动触发。

## 不适用场景

- 定位或修复 Bug；
- 代码质量、架构或安全 Review；
- 性能优化、重构或生成测试；
- 运行代码、访问数据库或验证真实外部服务响应；
- 需要跨仓库 Symbol Index、IDE 跳转或精确调用图的大型工程分析。

如果先要看懂代码、再决定是否修改，可以先显式使用本 Skill 获取心智模型，结束理解阶段后再提出独立的修改请求。
