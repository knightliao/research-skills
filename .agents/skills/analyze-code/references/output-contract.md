## 固定输出顺序

用户可见结果依次使用以下三个一级标题：

```markdown
# 一句话说明
# 核心流程
# 代码详细分析
```

不要在前面插入技术栈盘点、免责声明或逐行解释。

## 一句话说明

用尽量一句话回答代码整体完成什么功能。优先写业务或程序目的；片段不足以证明更大用途时，限定为“当前片段”或“当前方法”，不补造系统背景。

## 核心流程

用 3～8 个步骤还原正常主路径。每一步使用“短动作概括 + 一句必要说明”：

```markdown
1. **接收文章请求**：FastAPI 调用 `get_article()`，由此进入主处理路径。
2. **提取认证凭证**：入口从请求头取出 Token，交给身份查询使用。
```

- 概括使用并列的动宾短语；只扫读加粗部分也应能复述主路径。
- 说明交代当前输入、关键动作和结果流向，不把每个调用、参数或赋值拆成一步。
- 正常路径写完后，仅在确有改变结果的分支时增加“关键分支”表或短列表，不把异常路径混成后续步骤。

根据理解难点，默认最多补充一种关系视图：

| 主要难点 | 优先视图 |
| --- | --- |
| 多函数协作 | 调用链 |
| 连续数据转换 | 数据流 |
| 状态反复变化 | 状态迁移 |
| 多个提前返回或异常 | 分支结果表 |
| 初始化、运行、清理 | 生命周期 |

第二种视图只有在提供明显新增信息时才加入。关系视图不能逐字重复流程步骤。

## 代码详细分析

先给覆盖整个输入的“结构地图”，再按原始代码顺序解释语义单元。地图名称和颗粒度必须匹配代码形态：

| 输入形态 | 地图形式 |
| --- | --- |
| 单个函数或方法 | 逻辑阶段地图 |
| 单个类 | 职责与方法地图 |
| 完整文件 | 文件模块地图 |
| 路由、回调或事件代码 | 入口与处理链地图 |

短代码完整展开时，使用紧凑列表或三列表格，不显示全是“已展开”的状态列：

```markdown
| 逻辑阶段 | 代码范围 | 作用 |
| --- | --- | --- |
| 前置检查 | L1-L5 | 拦截取消请求 |
| 完成提交 | L6-L20 | 更新任务并提交事件 |
```

长代码或部分展开时增加“展开状态”，逐项标明已展开、部分展开或未展开。

每个语义单元至少包含稳定行号和解释；复杂或容易对错行的单元引用原始代码。标题可以携带局部作用：

````markdown
### L10-L14 — 发起认证请求

```python
response = await client.post(
    url,
    headers=headers,
    timeout=5,
)
```

这里完成一次请求；地址、Header 和超时共同定义同一操作。
````

简单连续定义、赋值或同类分支可以合并概括，不必为每行重复粘贴代码。解释当前单元新增的局部机制、数据变化、状态变化、控制流或副作用；不要重述一句话说明和整条核心流程。

## 稳定行号与语义覆盖

- 只对原始代码正文编号，从第一行开始记为 `L1`；围栏和上下文不计入，内部空行仍占行号。
- 不格式化、重排或修复代码后重新编号；闭合符号并入所属语义范围。
- 所有有实际语义的行必须进入某个单元，但各单元不要求相同篇幅。
- 多行调用必须整体解释，不得拆成“URL”“headers”“闭合括号”等机械段落。
- 解释代码在可见流程中的作用，不推测作者动机。

## 信息去重与未知

- 一句话、核心流程和详细分析各司其职，同一事实只完整解释一次。
- 外部实现、入口或环境未知时，在首次影响理解的位置说明；多个未知可以集中成一条“当前片段无法确认”，不要每段重复。
- 框架明确语义可以直接解释，部署、存储、网络拓扑和外部实现没有证据时保持未知。

## 覆盖状态

只有无法完整展开全部细节时才增加：

```markdown
## 本次覆盖状态

- 已展开：入口与主业务（L1-L120）。
- 部分展开：映射规则（L121-L210），已解释共同结构和关键差异。
- 未展开：辅助适配器（L211-L390），职责和主链路位置已在结构地图中说明。
```

覆盖状态不能替代完整结构地图和主路径，也不能用“其余后续继续”掩盖未知范围。
