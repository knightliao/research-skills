# 全球 AI Agent 增量雷达

## 目标

识别最近真正发生的新增变化，并回答：

- 相比此前能力或行业状态，增量在哪里；
- 是否影响 AI Agent 的产品形态、工程实现或交付成本；
- 是否影响企业应用、商业化或行业竞争；
- 技术负责人、产品负责人、业务负责人或创业者是否需要采取行动；
- 后续应使用哪些可验证指标持续观察。

覆盖产品与用户体验、Agent 工程架构、模型工具调用、浏览器与计算机操作、代码执行、多 Agent 协作、记忆与长期任务、MCP 与连接器、企业及垂直应用、开源生态、商业化、融资并购和竞争格局。

## 适用场景

- 生成每日或临时的全球 AI Agent 增量雷达；
- 评估某家公司、产品、技术方向、行业或地区近期是否出现实质变化；
- 为产品规划、技术选型、企业落地、竞争分析或创业判断提供近期信号；
- 在大量报道中核验时间、合并重复事件并筛出真正值得关注的变化。

## 不适用场景

- 汇总所有 AI 新闻、热搜或社交媒体讨论；
- 仅按媒体声量、公司知名度或融资金额制作榜单；
- 编写缺少近期增量要求的长期行业综述；
- 将未经核实的传闻、营销说法或演示视频包装成确定事实；
- 在证据不足时预测价格、投资回报或公司成败。

## 输入与默认值

- 默认研究范围：最近 72 小时；重点检查最近 24 小时。
- 背景窗口：仅在解释增量时补充最近 1–2 周背景，不把背景旧闻当作新事件。
- 默认地区：全球。
- 默认语言：简体中文。
- 默认读者：技术负责人、产品负责人、业务负责人和创业者。
- 可选输入：公司、产品、项目、地区、行业、主题、时间范围、时区、读者类型和输出语言。
- 用户明确指定上述输入时，优先采用用户要求；仍需标明实际研究截止时间与时区。

## 执行工作流

1. **确定研究边界**：确认当前日期、时区、截止时间和研究起点，分别标出 24 小时重点窗口与 72 小时默认窗口。
2. **明确关注方向**：根据用户要求和默认覆盖范围，列出本次重点主题、地区、行业及读者；不要让观察名单替代开放发现。
3. **搜索候选事件**：同时从观察池、主题检索和开放生态发现候选项，记录主体、事件、来源和候选时间。
4. **寻找原始来源**：优先定位官方公告、产品文档、代码仓库、论文、财报或监管文件；媒体报道只作背景或独立验证。
5. **核验时间**：分别确认来源发布时间、事件实际发生时间和功能可用时间，判断事件是否落入研究窗口。
6. **识别旧闻重发**：追溯最早可验证记录，排除文章更新、转载、摘要和旧内容重新传播造成的伪增量。
7. **合并重复报道**：围绕同一主体、能力、发布阶段和实际事件建立事件簇，按去重策略区分新事件、新证据与新阶段。
8. **拆分陈述类型**：为每个候选项分别记录事实、支撑证据、分析推断和行动建议，不得混写。
9. **评估重要性**：按 30 分制对新颖性、产品、工程、企业与商业化、竞争与生态、可信度评分，并记录理由。
10. **过滤低价值事件**：应用总分和可信度门槛；不为填满报告保留普通更新、纯评论或证据不足的高声量事件。
11. **分析影响**：说明产品形态、工程成本与交付、企业采用与商业化、竞争格局四方面中真正受到影响的部分；无证据的方面明确不作判断。
12. **提炼观察指标**：为每个重要事件给出可在后续验证的指标、数据来源、观察期限或触发条件。
13. **生成增量雷达**：结论先行，按重要性而非热度排序，明确新增事实、相对增量、影响、可信度和后续观察项。
14. **执行最终检查**：逐项核对时间、来源、去重、评分、事实与推断分离、语言和链接；删除不能通过检查的内容。

## 输出要求

- 开头写明研究截止时间、时区、覆盖窗口、地区、重点方向和面向读者。
- 先给出总体判断，再列重点事件和一般重要事件；每项包含事件事实、相对增量、证据与可信度、影响判断、评分及后续指标。
- 所有重要事实提供可直接访问且能支撑该事实的来源链接，并区分事件发生时间与报道时间。
- 推断使用“这表明”“可能意味着”等明确措辞；建议说明适用对象、行动条件和风险。
- 默认使用简体中文；公司名、产品名、项目名和技术标识保留官方名称。
- 如果没有事件达到 24–30 分的重点事件门槛，明确写出：**今天没有重大突破。** 若存在 18–23 分的一般重要事件，可在其后如实列出；不得用低价值新闻填充。

## 硬性工作规范

- 原始来源优先；二手来源只用于补充背景和独立验证。
- 不得把路线图或未来规划写成已实现能力，不得把小范围测试写成全面上线。
- 不得把营销表述、演示视频、基准领先、媒体数量或融资金额直接等同于真实能力或重大影响。
- 未经核实的传闻不得成为核心结论；信息冲突或无法核实时必须降级表达或排除。
- 同一事件只计一次，不因重复报道增加评分或篇幅。
- 每条结论都必须能追溯到证据；没有证据时明确标为推断，不得补造事实。
- 不写入 API Key、Token、Cookie、密码、私人数据或内部资料。
- 不为追求数量降低收录门槛，也不强行覆盖所有方向。

- [ ] 每项是否核验事件发生时间、功能可用时间和来源发布时间？
- [ ] 是否优先使用原始来源，并为关键事实提供直接证据？
- [ ] 是否排除旧闻重发、重复报道、纯媒体评论和低价值更新？
- [ ] 是否按规则评分，并满足总分与可信度门槛？
- [ ] 是否清楚区分事实、证据、推断和建议？
- [ ] 是否解释相对增量及产品、工程、商业化或竞争影响？
- [ ] 是否给出可验证的后续观察指标？
- [ ] 没有重大事件时，是否明确写出“今天没有重大突破。”？
- [ ] 所有链接是否可用，且报告语言和专有名词是否符合要求？
