# 观察池管理规则

## 作用与边界

观察池用于提高持续研究的覆盖稳定性，帮助发现重点主体的更新和维护查询词。它不是行业排名、投资推荐或封闭白名单，也不能替代每次研究中的开放搜索。

具体结构化名单只在 `../assets/watchlist.csv` 中维护，该文件是公司、产品、开源项目和协议条目的单一事实来源。本文件只定义分类与管理规则，不重复维护完整名单；本阶段不大规模扩充 `watchlist.csv`。

## 分类框架

每个对象可有一个主要分类和必要的辅助标签：

- 基础模型与平台；
- 通用 Agent 产品；
- 编程与软件工程 Agent；
- 浏览器与计算机操作 Agent；
- 企业工作流 Agent；
- 垂直行业 Agent；
- Agent 开发框架；
- 工具协议和连接器生态；
- 记忆、上下文、评估、安全和可观测性；
- 开源新项目；
- 商业化与企业应用案例。

分类用于组织检索，不代表评分高低。跨类别对象选择最能解释其当前核心价值的主分类，避免为同一对象建立重复条目。

## 纳入标准

满足以下一项或多项且存在可追溯公开来源时，可加入观察池：

- 发布或维护具有实质自主规划、工具使用、环境交互或任务执行能力的产品；
- 提供模型工具调用、浏览器或计算机操作、代码执行、多 Agent、记忆或长期任务等关键能力；
- 维护被实际采用的 Agent 框架、MCP、工具协议、连接器、评估、安全或可观测性项目；
- 已出现可验证的企业部署、付费模式、客户采用或垂直行业工作流；
- 可能改变分发、标准、开发者选择、成本结构或竞争格局；
- 是观察池之外快速出现的新项目，且已有代码、文档、用户证据或独立验证，而不只是概念宣传。

对象知名度、融资金额、媒体数量和名称中是否包含 Agent 都不能单独作为纳入理由。

## 跟踪级别与调整

根据近期证据设置跟踪级别，具体字段是否写入 CSV 由其既有表头和后续维护方案决定，不在本文件创建第二套记录。

- **升级**：连续出现高质量发布、采用、生态增长或竞争响应；提高检索频率和主题覆盖。
- **降级**：长期只有营销内容、更新缺乏实质增量、使用证据减弱或与 AI Agent 主题的相关性下降。
- **暂停跟踪**：短期无维护、来源不可用、产品处于静默状态或信息噪声长期高于价值；保留历史身份以便恢复。
- **剔除**：确认项目终止、仓库归档且无活跃继任者、产品完全退出 Agent 方向，或条目重复及最初纳入依据错误。

任何升级或降级都记录可核验理由和日期，不因单次媒体热度永久改变级别。暂停和剔除不等于删除历史关系；需要保留重定向、继任项目或最终状态。

## 观察池外发现

每次研究都同时执行“池内检查”和“开放发现”：

1. 按本次关注方向扫描结构化观察池；
2. 对关键能力、协议、行业、地区和使用场景进行不带公司名的主题检索；
3. 检查新发布的代码、论文、连接器、产品目录、开发者讨论和企业案例；
4. 从竞争对手、集成伙伴、客户、维护者和引用关系扩展候选对象；
5. 对观察池外对象应用相同的信源、去重和评分规则，通过纳入标准后再建议加入 CSV。

不得因为对象尚未进入观察池而降低评分或排除，也不得为了维护观察池而把未达报告门槛的对象写入主报告。

## 避免大公司偏差

- 按技术能力、使用场景、地区和行业组织检索，而不是只搜索知名公司名称。
- 为创业公司、开源项目、非英语市场和垂直行业保留独立发现路径。
- 对所有对象使用同一评分门槛，不用品牌声量替代产品、工程或采用证据。
- 记录来源可见性偏差：大公司的公告和媒体覆盖更充分，不代表其增量天然更大。
- 不为追求“多样性”强行收录低分项目；多样性要求适用于候选发现，不改变证据标准。

## 创业公司、开源项目与垂直行业

- 创业公司重点观察可用产品、真实客户、定价、部署周期、单位经济性和团队执行，而非只看融资。
- 开源项目重点观察 Release、Commit、维护者活跃度、许可证、可复现性、集成、下载或使用证据；Star 仅作辅助信号。
- 垂直行业 Agent 重点观察数据与系统接入、合规责任、人工复核、任务成功率、交付成本和付费客户。
- 对新对象先标记为候选，完成身份、来源、活跃状态和类别核验后再进入结构化名单。

## 生命周期与身份变更

- **改名**：更新当前官方名称，保留旧名称作为检索别名，避免生成重复条目。
- **收购或合并**：记录新归属、交易阶段和产品是否继续独立维护；不要立即把历史事件并入收购方。
- **转型**：更新主要分类和跟踪理由，保留转型前身份用于去重；若不再涉及 AI Agent，降级或剔除。
- **停止维护**：结合归档状态、最后有效更新、维护者说明和替代项目判断；不能只因短期无 Commit 认定终止。
- **分拆或继任**：为实质独立的新项目建立新条目，并在两者之间记录关系，避免将继任项目误判为旧闻。

维护 `watchlist.csv` 时只写公开、非敏感、可持续核验的信息，不写联系人隐私、内部资料、凭据或未经证实的负面判断。
