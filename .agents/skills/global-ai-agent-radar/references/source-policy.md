## 核心原则

- 原始来源优先，用最接近事件、可直接核验的证据支持核心事实。
- 二手来源用于补充背景、提供外部视角和独立验证，不能替代可获得的原始来源。
- 社交媒体和社区内容主要用于发现线索、观察实际反馈，不直接承担核心结论。
- 未经核实的传闻不能成为确定性结论。
- 区分已发布、可申请测试、有限灰度、全面开放和未来规划，不把阶段混写。
- 将营销主张视为待验证陈述，不直接当作客观事实。

## 信息源优先级

按以下顺序寻找证据；优先级高不代表内容自动真实，仍需检查时间、范围和可验证性。

1. **可验证的一手材料**：正式产品文档、更新日志、API 文档、GitHub Release 与代码、论文及其制品、财报、监管文件、官方定价页、状态页和公开客户案例。
2. **主体直接声明**：公司或项目官方博客、新闻稿、官方账号、负责人具名说明。声明可以证明“主体说过什么”，不一定证明能力已经实现。
3. **权威独立来源**：有编辑与纠错机制、作者具名、引用具体证据的专业媒体、研究机构或行业数据库。
4. **社区与用户材料**：开发者论坛、Issue、Discussion、独立测试、用户反馈和公开演示复现。
5. **匿名或不可追溯材料**：匿名爆料、截图转述、聚合页和无原始链接的转载，仅作为待核线索。

## 一手来源的定义

一手来源是事件主体、直接参与方或具有法律及技术记录责任的系统发布的材料，并且能够定位到具体事实。常见形式包括：

- 产品与技术：官方文档、更新日志、API 变更、可访问产品界面、状态页和官方仓库；
- 开源：Release、Tag、Commit、维护者说明、Issue、许可证和可运行制品；
- 研究：论文原文、附录、数据集、评估代码和作者正式说明；
- 商业与公司：财报、投资者材料、合同主体公告、定价页和具名客户案例；
- 融资与监管：公司或投资方公告、证券及竞争监管文件、法院或政府公开记录。

官方材料若只包含愿景、路线图或无法复现的营销主张，只能证明其发布了该声明，不能单独证明能力、规模或效果。

## 各类来源的使用规则

### 官方博客、产品文档和发布记录

- 用博客确认官方叙事，用产品文档、更新日志、访问条件和定价页确认实际能力与开放范围。
- 文档可能持续更新且不保留原始日期；应结合更新日志、存档、Release 或其他带时间记录的材料核验。
- 明确区分宣布、邀请测试、Preview、Beta、灰度、区域开放和 General Availability（正式可用）。

### GitHub 与开源制品

- 确认仓库归属、Release 或 Tag、Commit 时间、代码或包是否实际可得，以及许可证与维护状态。
- 博客、Release、包发布和产品上线若描述同一版本，应相互核对，不重复作为多个事件。
- Star、Fork、下载量和榜单可作为生态信号，但不能单独证明质量、采用或生产可用性。

### 论文与评估

- 标明预印本、会议版本或正式发表状态，并区分首次公开日期与修订日期。
- 检查任务定义、数据集、基线、限制、利益相关关系和代码或数据是否开放。
- 论文结论只适用于其证据覆盖的设置；不得将实验结果直接写成生产能力或商业价值。

### 财报、监管文件和交易材料

- 优先使用具有法律责任的财报、监管披露和交易方公告，保留金额、币种、期间和口径。
- 将已签署、已宣布、等待审批和已交割分别表述；融资传闻只有在独立核实后才能进入主报告。
- 客户数、收入、使用量等数据必须保留统计周期、定义和公司自报属性。

### 权威媒体

- 用于独立验证、采访补充、竞争背景和难以从官方材料获得的交易细节。
- 优先采用具名作者、明确发布日期、原始链接、直接采访和公开纠错机制的报道。
- 多家媒体引用同一新闻稿或同一匿名消息不构成多重独立验证，也不能因报道数量提高可信度。

### 社交媒体和社区内容

- 可用于发现新项目、故障、限制、真实使用反馈和待核实线索。
- 核对账号身份、原始发布时间、上下文、是否可复现，以及内容是否被编辑或删除。
- 单条帖子、截图、点赞或转发量不能证明广泛采用；社区反馈应标明样本有限和选择偏差。

### 匿名爆料和未经确认信息

- 不得作为核心事实、评分依据或行动建议的唯一证据。
- 只有在信息具有明显公共价值且获得可靠独立验证时，才可作为“待确认信号”提及。
- 不公开扩散私人信息、内部材料、凭据或可能伤害个人的未核实指控。

## 时间与发布阶段

每个候选事件至少记录三类时间：

1. **来源发布时间**：文章、公告、帖子或文件公开的时间；
2. **事件发生时间**：签约、发布、合并、开源或其他动作实际发生的时间；
3. **能力可用时间**：用户或开发者能够实际访问该能力的时间及适用范围。

媒体报道进入时间窗口，不代表事件本身是新事件。若官方先预告、随后测试、再正式开放，应按去重策略判断是同一事件的新阶段还是旧信息重发。无法确定时间时，写明“实际发生时间尚无法核实”，不得默认采用报道时间。

## 来源冲突与无法核实

发生冲突时：

1. 比较来源是否直接参与事件、是否承担法律或技术记录责任、证据是否可复查、口径是否一致；
2. 回到原始文档、代码、监管记录或完整上下文，不按媒体数量投票；
3. 明确列出冲突点及各自口径，避免拼接出来源都未表达的结论；
4. 若关键事实仍不能确认，降低可信度评分，并从确定性主结论中移除。

无法核实时使用限定表达，例如：“官方尚未提供可复现证据”“目前仅有单一媒体引述匿名来源”“开放范围尚不明确”。不要用“据悉”“业内认为”等模糊措辞掩盖证据缺口。

## 引用、证据与陈述边界

- 每项重要事实都附能够直接支撑该事实的链接，优先链接原文、具体文档页、Release、论文或监管条目，而非搜索结果或聚合页。
- 引用附近写清来源主体、发布时间、事件时间和证据能证明的范围；同一链接不能支撑其未涉及的推论。
- 关键主张至少有一项能直接支撑该事实的高质量证据。若无法获得一手来源，须使用至少两项真正独立且口径一致的可靠二手来源，并明确说明一手证据缺口；若主要依赖主体自述，尽可能补充独立验证。
- 明确标注四类内容：**事实**是来源直接支持的陈述；**证据**是可复查材料；**推断**是基于事实的解释；**建议**是面向特定读者的行动选择。
- 推断使用“表明”“可能意味着”“若得到验证”等措辞，并说明依据和不确定性；不得将推断倒写成事实。
