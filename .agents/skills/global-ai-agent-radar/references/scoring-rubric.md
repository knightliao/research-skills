# 评分规则

## 使用方法

对去重后的每个候选事件按 6 个维度分别打 0–5 分，总分 30 分。先记录事实和证据，再独立评分并写出每个维度的简短理由。2 分和 4 分用于相邻锚点之间的情况，不得为了跨过收录门槛而向上取整。

评分衡量的是本次事件相对于此前状态的增量，不是公司规模、媒体热度或长期愿景。

## 评分维度

以下 6 项是完整评分维度，全部位于 JSON 的 `scores` 对象中，每项 0–5 分并计入 `total_score`：

| 序号 | 中文名称 | JSON 字段 |
| --- | --- | --- |
| 1 | 新颖性 | `novelty` |
| 2 | 产品影响 | `product_impact` |
| 3 | 工程与技术影响 | `engineering_impact` |
| 4 | 企业应用与商业化影响 | `commercialization_impact` |
| 5 | 行业竞争与生态影响 | `ecosystem_impact` |
| 6 | 信息可信度 | `credibility` |

`confidence` 不属于这 6 个评分维度，不计入 `total_score`。它是独立的“判断置信度”分类字段，取值为 `high`、`medium` 或 `low`。

| 评分维度（JSON 字段） | 0 分 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- | --- |
| **新颖性（`novelty`）** | 旧闻重发、重复报道或没有可识别的新事实。 | 仅有命名、包装、轻微参数或宣传变化，实际状态基本未变。 | 出现可验证的新能力、新阶段、新采用证据或重要限制变化。 | 首次出现可复现、可能改变既有范式或建立新类别的增量。 |
| **产品影响（`product_impact`）** | 不改变用户价值、体验或工作流。 | 只影响很小范围用户或边缘操作，替代方案充分。 | 明显改善关键任务的完成方式、可用范围、可靠性或成本。 | 重塑广泛用户的核心工作流、交互入口或产品边界。 |
| **工程与技术影响（`engineering_impact`）** | 没有工程或技术变化，或只有营销表述。 | 仅是浅层封装、配置调整或局部性能变化。 | 对架构、工具调用、执行、记忆、评估、安全、可靠性或交付成本产生实质影响。 | 解锁此前难以实现的能力，或显著改变系统架构、性能边界和工程经济性。 |
| **企业应用与商业化影响（`commercialization_impact`）** | 没有采用、收入、定价或企业工作流方面的新证据。 | 只有意向、试点宣传或缺少口径的单一案例。 | 出现可核实的定价变化、客户采用、规模化部署或明确商业模式信号。 | 可能显著改变采购、部署、单位经济性或大规模企业工作流。 |
| **行业竞争与生态影响（`ecosystem_impact`）** | 对竞争位置、标准或生态没有可见影响。 | 影响局限于单一主体，外溢和响应信号较弱。 | 改变关键竞争维度、开发者选择、协议采用、分发渠道或合作关系。 | 可能重排行业结构、形成或打破平台控制、确立关键标准或触发广泛跟进。 |
| **信息可信度（`credibility`）** | 来源明显错误、互相矛盾且无法解释，或没有可追溯证据。 | 只有匿名、单一社区线索、截图或不可验证的主体声明。 | 有可核验的一手来源，或两个真正独立且口径一致的可靠来源，但仍存在限制。 | 有直接可复查的一手制品或法定记录，并有独立证据确认关键事实与适用范围。 |

## 收录阈值与分类优先级

总分必须由上述 6 项评分重新计算：

```text
total_score = novelty
            + product_impact
            + engineering_impact
            + commercialization_impact
            + ecosystem_impact
            + credibility
```

输入或研究记录中的已有 `total_score` 只能用于一致性核对，不得替代重算结果；`confidence` 不参与加总。

`credibility`（信息可信度）评价来源质量、证据强度和事实可核验程度；`confidence`（判断置信度）表示执行 Agent 对当前综合判断的把握程度。两者不要求一一映射，但都会参与后续分类。

按以下顺序分类，前面的规则优先：

1. 信息可信度为 0–1 分时，排除出最终事件清单。
2. `confidence=low` 时，只能作为待验证信号，高总分不能覆盖此规则。
3. 信息可信度为 2 分时，只能作为待验证信号，不受总分和 `confidence` 影响。
4. 重算总分 24–30 分、信息可信度至少 3 分且 `confidence` 为 `high` 或 `medium`：重点事件。
5. 重算总分 18–23 分、信息可信度至少 3 分且 `confidence` 为 `high` 或 `medium`：一般重要事件。
6. 重算总分低于 18 分、信息可信度至少 3 分且 `confidence` 为 `high` 或 `medium`：通常不进入报告；只有执行 Agent 判断值得继续验证时，才简要保留为待验证信号。

是否值得验证属于研究判断，不由校验脚本根据分数自动决定。若总分很高但 `confidence` 较低或信息可信度不足，应说明潜在影响与待验证条件，不得用潜在影响替代事实确认。

## 评分边界

- 新颖性只评价“新发生了什么”，不重复计算其他维度的影响。
- 产品影响评价用户价值和工作流；工程与技术影响评价实现方式、性能边界、可靠性及成本。
- 企业应用与商业化影响需要采用、定价、部署或收入证据；行业竞争与生态影响关注外部主体、标准、平台和开发者选择。
- 可信度评价证据质量，不评价事件是否令人兴奋。缺少证据必须降分。
- 同一事实可以支持多个维度，但每个维度必须解释不同的影响机制，不能复制同一句理由。

## 防偏规则

- 不因公司知名度、品牌影响力或高管身份自动加分。
- 不因融资金额较大自动判断为重大突破；融资需证明会改变产品、人才、市场或竞争条件。
- 不因产品名称包含 Agent 就视为 AI Agent 进展；必须存在自主规划、工具使用、环境交互或任务执行等实质能力变化。
- 不因发布演示视频就视为能力已经成熟；应核验访问范围、复现条件、成功率、限制和真实用户证据。
- 不因基准测试领先就自动判断商业价值高；应检查任务代表性、评估设计、成本、延迟、稳定性和可部署性。
- 同一事件被多家媒体报道不能重复计分，也不能提高新颖性或影响分。
- 同一新闻稿被多家媒体转载不构成独立验证，不能提高可信度。
- 信息可信度较低时，即使潜在影响很大，也不能直接列为确定性重大事件。
- 不为凑够事件数量调整分数，也不为覆盖所有方向降低门槛。
