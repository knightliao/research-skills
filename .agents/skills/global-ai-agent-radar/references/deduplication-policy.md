# 去重与增量判断策略

## 判断单位

以“主体 + 对象或能力 + 动作 + 发布阶段 + 适用地区或人群 + 实际发生时间”描述一个基础事件。先为候选材料建立事件簇，再评分和写作；报道数量不是事件数量。

对每条新材料先归入以下类型：

- **新事件**：此前不存在的产品、能力、交易、协议、项目或采用事实首次实际发生；
- **同一事件的新证据**：补充了数据、复现结果、客户案例或限制，但事件阶段未改变；
- **同一事件的新阶段**：从预告、测试、灰度、区域开放推进到更广泛或正式可用；
- **旧闻重发**：没有新增事实，只是转载、重新传播、文章更新或换标题；
- **纯媒体评论**：只有观点、预测或解读，没有新的可验证事件；
- **真正影响判断的新信息**：新材料足以改变可信度、评分、适用范围或行动建议。

## 处理流程

1. 提取主体、产品或项目、核心动作、能力、版本、发布阶段、地区、用户范围及三类时间。
2. 追溯最早可验证的一手记录，确定事件锚点和此前已知状态。
3. 检索同一主体、产品、版本、交易或能力的其他材料，建立事件簇。
4. 比较新材料是否改变事实、阶段、范围、评分或结论，而不是只比较标题和发布日期。
5. 为事件簇保留一个主条目，其他材料作为证据、背景、阶段更新或排除记录。
6. 仅对最终主条目评分；不得因材料数量累加新颖性、可信度或影响。

## 常见情形

### 多家媒体报道同一事件

合并为一个事件。选择最接近原始事实且证据最完整的来源作为主证据，其他真正独立的报道用于验证或补充背景。若多家媒体都引用同一新闻稿或匿名消息，视为单一信息链。

### 官方公告与媒体解读

通常合并。官方公告用于确认主体声明、时间和范围，媒体解读用于外部背景、采访或质疑。只有媒体披露了可独立验证且会改变判断的新事实，才标记为“新证据”或“判断更新”。

### 同一产品在不同地区分批上线

若只是既定计划中的相同能力扩区，记录为同一事件的新阶段并更新覆盖范围。若新地区带来不同功能、监管许可、商业模式、客户群或显著规模影响，可作为单独增量，但必须说明与原事件的关系。

### 从预告、测试、灰度到正式发布

预告只证明计划存在；测试、灰度和正式发布分别代表不同可用阶段。阶段推进带来真实访问范围、能力、稳定性或定价变化时，可作为“同一事件的新阶段”单独收录。若后续公告只是重复此前承诺且没有实际开放变化，则合并或排除。

### 旧文章重新传播

以事件实际发生时间和最早公开记录为准。文章被更新、转载或重新进入热榜但没有新增事实时，标为旧闻重发并排除。若更新部分提供新的可验证数据，只将新增部分视为新证据。

### 融资消息与产品消息

融资和产品发布原则上是两个事件，分别评价资本与产品增量。若产品消息只是融资稿中的背景描述，不另建产品事件；若资金用途仍是计划，不写成能力已经交付。只有二者在事实和影响机制上不可分割时才合并，并分别说明证据。

### 同一家公司同一天发布多个相关更新

属于同一发布包、同一产品和同一用户价值主张的更新应合并，内部列出关键子变化。涉及不同产品线、独立能力、不同发布阶段或不同影响路径，且各自达到收录门槛时，可拆分，但不得重复计算共享证据和影响。

### GitHub 版本、博客公告与产品上线

若 Release、博客和产品上线对应同一版本，合并为一个事件，并分别用代码制品、官方解释和可用状态支撑不同事实。若代码在较晚时间才开放，或后续版本带来实质能力变化，可记录为新阶段或新事件。仅修改文档、版本号或发布说明而无实际变化时不构成增量。

### 补充数据或客户案例

默认归为同一事件的新证据。若新数据首次证明规模化采用、推翻原结论、显著改变可信度或使评分跨越收录层级，可单独发布“判断更新”，同时链接原事件并只陈述新增部分。

## 应当合并的情况

- 描述同一主体在同一时间完成的同一动作，仅来源、标题或叙事角度不同；
- 官方公告、媒体报道、社交帖子和社区讨论围绕同一发布；
- 同一版本的代码、文档、博客和产品页面同步更新；
- 新材料只重复已知功能、融资数字、合作关系或客户名称；
- 分批上线没有改变能力、访问级别或影响判断。

## 可以单独收录的情况

- 出现新的实际动作，而非对原动作的重复描述；
- 发布阶段实质推进，并改变可用性、规模、稳定性、定价或风险；
- 新证据足以改变可信度、总分层级、核心结论或行动建议；
- 新地区、客户或行业场景带来不同监管条件、商业模式或规模证明；
- 后续版本改变关键能力、接口、架构、许可证或生态关系；
- 融资、并购、产品发布和开源动作各自具有独立事实与影响，且分别达到门槛。

单独收录时必须说明“相对上一事件新增了什么”，并引用原事件或此前状态。无法明确回答这一问题时，应合并或排除。
