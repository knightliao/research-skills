# Global AI Agent Radar 用户使用示例

## 这个 Skill 适合什么

`global-ai-agent-radar` 用于研究近期全球 AI Agent 在产品、技术、生态、企业应用、商业化、融资和竞争方面的真正增量。它会核验事件时间、优先寻找原始来源、合并重复报道、按证据和影响评分，并给出后续可验证指标。

它适合需要近期决策信号的技术负责人、产品负责人、业务负责人和创业者，不是“把所有 AI 新闻收集到一起”的新闻摘要工具。

## 调用方式

通过当前宿主提供的 Skill 入口选择 `global-ai-agent-radar`，再发送研究范围和关注重点。不同宿主的具体选择方式可能变化；完整宿主说明见仓库根 README。

## 使用前准备

- 时间范围和时区；不指定时默认研究最近 72 小时，重点检查最近 24 小时。
- 关注的公司、产品、技术方向、行业、地区或主题；不指定时默认覆盖全球。
- 目标读者和希望支持的决策；不指定时面向技术、产品、业务负责人和创业者。
- 如果要求维护观察池，明确要核验或调整的对象与范围。

## 快速开始

下面是最短的可复制输入：

```text
请生成最近 72 小时的全球 AI Agent 增量雷达。

重点筛选真正可能影响 Agent 产品形态、工程落地、商业化机会、企业应用或创业方向的信息。
不要生成泛泛的 AI 新闻摘要。
```

**预期交付**

一份注明截止时间、时区、覆盖窗口、地区、重点方向和读者的中文增量雷达。报告先给总体判断，再按证据和重要性列出事件事实、相对增量、来源、影响、评分、风险、行动建议与未来 1～4 周的观察指标；没有足够增量时会明确写“今天没有重大突破”，不会用低价值新闻填充。

## 常见场景

### 场景一：默认 72 小时全球增量雷达

**适用场景**

需要了解最近三天真正值得产品、工程或业务团队行动的 AI Agent 变化。

**使用前准备**

- 可选的时区和研究截止时间；
- 可选的重点主题或排除方向；
- 希望支持的决策。

**可复制输入**

```text
请生成最近 72 小时的全球 AI Agent 增量雷达。

重点筛选真正可能影响：
- Agent 产品形态；
- 工程落地；
- 商业化机会；
- 企业应用；
- 创业方向

的信息。

不要生成泛泛的 AI 新闻摘要。
```

**预期交付**

- 研究边界和今日总体判断；
- 重点事件、一般重要事件或少量待验证信号；
- 每项事件的直接证据、时间、真正增量、评分与不确定性；
- 面向不同负责人的有条件行动建议；
- 观察池调整建议和后续验证指标。

**注意事项**

报告按事件实际发生和能力可用时间判断是否属于近期增量，不会因为报道刚发布就把旧事件当作新变化。

### 场景二：公司、产品或技术方向的专题雷达

**适用场景**

需要聚焦某家公司、产品、技术方向、行业或地区，判断近期是否出现了实质变化。

**使用前准备**

- 专题对象或关键词；
- 时间范围；
- 最关心的产品、工程、商业化或竞争问题。

**可复制输入**

```text
请生成最近 7 天关于 <公司、产品或技术方向> 的 AI Agent 专题雷达。

重点回答：
- 新变化是什么；
- 相比此前有什么增量；
- 对产品和工程意味着什么；
- 哪些判断仍需继续观察。
```

**预期交付**

围绕指定专题组织的增量判断，而不是完整全球新闻清单。关键事实仍会经过时间核验、来源分级、去重和评分，并明确证据缺口。

**注意事项**

较长时间范围会按用户要求执行，但报告仍会区分窗口内事件和仅用于解释增量的背景材料。

### 场景三：面向特定决策者

**适用场景**

同一批近期变化需要从特定角色的决策视角排序和解释。

**使用前准备**

- 目标读者；
- 当前决策或约束；
- 重点关注的指标。

**可复制输入**

```text
请生成最近 72 小时的全球 AI Agent 增量雷达。

目标读者：<产品负责人 / 技术负责人 / 创业者 / 投资研究者>

重点输出对该读者最有决策价值的信息，并说明行动条件、风险和后续验证指标。
```

**预期交付**

研究标准保持不变，但事件排序、影响分析和行动建议会面向指定读者。没有证据支持的影响维度会明确不作判断。

**注意事项**

读者视角只改变分析重点，不会降低可信度和收录门槛，也不会把推断改写成事实。

### 场景四：显式维护结构化观察池

**适用场景**

需要核验并更新 Skill 的结构化观察池，例如升级、降级、暂停、剔除或新增对象。

**使用前准备**

- 明确要求进入观察池维护模式；
- 要核验的对象或变更范围；
- 支持调整的公开证据；
- 可访问的仓库工作树。

**可复制输入**

```text
请进入观察池维护模式，核验并更新以下对象：

- 对象：<公司、产品、项目或协议>
- 建议动作：<新增 / 升级 / 降级 / 暂停 / 剔除>
- 已知依据：<公开来源或待核验线索>

只应用证据支持且属于上述范围的变更。修改后运行仓库已有校验和测试，检查 git diff；不要提交或推送。
```

**预期交付**

对对象身份、官方来源、分类、状态、调整理由和复核日期的核验结果；证据充分时更新 `assets/watchlist.csv`，随后报告实际修改、校验结果和未决问题。

**注意事项**

普通日报和专题研究默认只读使用观察池，只能提出调整建议。只有用户明确要求维护或更新观察池时，才允许写入该 CSV。

## 不适用场景

- 汇总所有 AI 新闻、热搜或社交媒体讨论：应使用普通新闻搜索或摘要流程。
- 只追求新闻数量、公司榜单或融资金额排序：这些信号不能替代真实增量与证据。
- 不要求增量、影响判断和可验证指标的普通摘要：直接使用通用搜索或摘要工具更合适。
- 与 AI Agent 无关的泛科技新闻或长期行业综述：应选择对应领域的研究流程。
