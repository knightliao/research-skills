# 反面报告示例

> 以下内容为故意编写的错误示例，请勿模仿。

## 错误报告正文

### AI Agent 行业全面爆发，未来可期

今天 AI Agent 行业迎来历史性突破，各家公司都在大力发展，值得持续关注。

1. 著名公司 FamousCloud 正式上线 Super Worker，评分 30 / 30。媒体今天报道称，它将在下个月邀请一小批客户测试，因此产品已经全面开放，必将重塑所有企业工作流。
2. FamousCloud 发布 Super Worker，标志着 AI Agent 进入新时代。另一家媒体也报道了同一新闻，所以这是第二项重大事件。
3. FlowOS 已向全球用户开放新 Agent。实际上官方只说 2% 的测试账号可以看到灰度入口，但这已经证明产品成熟。
4. Nova Example Systems 完成 2 亿美元融资，因此 Nova Coding Agent 在技术上实现重大突破，肯定已经领先竞争对手。
5. ExampleAI 发布了一段 Atlas Agent 演示视频，视频中任务成功，所以它在任何企业环境中都能稳定运行。
6. FamousCloud 是全球知名公司，研发实力强，因此即使没有技术文档，也应该给最高评级。
7. 两周前 Atlas Agent 更换了图标，今天又被媒体转发。这说明产品体验出现重大增量。
8. 某论坛有人说 Nova Coding Agent 的成功率达到 99%，这证明它已经完全替代程序员。

这些新闻充分说明 AI Agent 赛道正在高速发展、前景广阔。建议所有企业立即全面接入，大力投入，持续关注行业发展。

## 错误分析

### 1. 只罗列新闻，没有增量判断

- **错在哪里**：正文只复述标题，没有回答相对此前状态新增了什么。
- **违反原则**：增量优先、结论必须基于可验证变化。
- **正确做法**：明确此前状态、本次新增事实、发布阶段和影响机制；无法指出增量时不收录。

### 2. 使用空泛表达

- **错在哪里**：“大力发展”“未来可期”“值得关注”“进入新时代”没有可检验含义。
- **违反原则**：规则和判断应具体、可执行。
- **正确做法**：说明受影响的产品、工程或商业环节，并给出指标、期限和验证条件。

### 3. 混淆事实和推断

- **错在哪里**：从一条媒体报道直接推出“重塑所有工作流”和“完全替代程序员”。
- **违反原则**：事实、证据、推断和建议必须分离。
- **正确做法**：先陈述来源支持的事实，再用限定措辞表达推断，并说明不确定性。

### 4. 把预告写成正式上线

- **错在哪里**：FamousCloud 只预告下个月测试，报告却写成已经正式上线。
- **违反原则**：不得把未来规划表述成已实现能力。
- **正确做法**：标为预告或待验证信号，等到实际开放后再判断新阶段。

### 5. 把灰度测试写成全面开放

- **错在哪里**：2% 测试账号的灰度入口被写成全球可用。
- **违反原则**：必须区分有限测试、灰度、区域开放和正式可用。
- **正确做法**：保留访问比例、地区和账号限制，不外推到全部用户。

### 6. 把融资金额视为技术突破

- **错在哪里**：融资只证明交易声明，不能证明产品能力、可靠性或采用。
- **违反原则**：融资金额不自动提高技术或产品评分。
- **正确做法**：融资与产品事件分别评分；只有资金带来可验证交付变化时才分析实际影响。

### 7. 因公司知名度给高评级

- **错在哪里**：FamousCloud 因品牌知名度被直接评为 30 分。
- **违反原则**：所有主体使用相同证据和评分门槛。
- **正确做法**：逐项评价新颖性、产品、工程、商业化、竞争和可信度，不给品牌加分。

### 8. 重复收录同一事件

- **错在哪里**：FamousCloud 的同一发布因两家媒体报道被计为两个事件。
- **违反原则**：报道数量不是事件数量，同一事件只能评分一次。
- **正确做法**：建立事件簇，用官方材料作主证据，独立媒体只用于验证或补充。

### 9. 混淆报道时间和事件发生时间

- **错在哪里**：两周前的图标更新因今天被转发而被当作新事件。
- **违反原则**：研究窗口以事件发生和能力可用时间为核心，不以转载时间代替。
- **正确做法**：追溯最早记录；没有新增事实时标记为旧闻重发并排除。

### 10. 没有来源和证据说明

- **错在哪里**：报告没有提供官方文档、Release、产品页面或可核验链接。
- **违反原则**：重要事实必须能追溯到直接证据。
- **正确做法**：提供能支撑具体事实的原始链接，并说明证据类型和证明范围。

### 11. 没有风险与不确定性

- **错在哪里**：把所有声明写成确定结论，没有访问限制、样本范围或失败情况。
- **违反原则**：证据不足和适用边界必须显式表达。
- **正确做法**：列出未覆盖场景、来源偏差、复现缺口和可能推翻判断的条件。

### 12. 没有后续可验证指标

- **错在哪里**：没有成功率、人工接管率、成本、部署数量或观察期限。
- **违反原则**：每个重要判断都应转化为可持续观察的指标。
- **正确做法**：为未来 1–4 周指定指标、数据来源和判断触发条件。

### 13. 为凑篇幅加入低价值新闻

- **错在哪里**：图标变化和重复报道被包装成重大增量。
- **违反原则**：低于收录阈值的普通更新不得用于填满报告。
- **正确做法**：删除低价值事件；没有重点事件时明确写“今天没有重大突破”。

### 14. 给出不可执行建议

- **错在哪里**：“全面接入”“大力投入”“持续关注”没有对象、条件、风险或验证步骤。
- **违反原则**：建议必须面向明确读者并可执行。
- **正确做法**：限定试验范围、负责人、期限、成功指标和停止条件，先验证再扩大投入。
